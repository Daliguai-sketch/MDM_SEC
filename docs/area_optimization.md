# AES 与包缓冲面积优化说明

## 1. 同条件的综合结果

下表比较优化前提交 `711947b1c08a16688d1521be45426868f4fd03e9` 与当前 RTL。工具均为 Yosys 0.64（YoWASP），使用同样的 `synth -noabc; check -assert; stat`；顶层参数 `MAX_BYTES=2048`。内存被映射为触发器和多路选择器，表中是**未映射到工艺库的通用单元个数**，不同单元都按 1 个计数，**不是标准单元实际面积、门等效数、SRAM 面积或时序结果**。

| 比较对象 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 单个 AES 原语，低面积配置 | 7,321 | 2,177 | -70.26% |
| 仅输入缓存地址计算，仍为 2048 字节、双读口 | 56,207 | 55,926 | -0.50% |
| 两个缓存模块之和 → 一个共享缓存模块 | 96,017 | 56,510 | -41.15% |
| 顶层，默认低面积 AES | 157,502 | 107,643 | -31.66% |
| 顶层，保留 5 拍高速 AES | 157,502 | 117,931 | -25.12% |
| 两份缓存的存储位 → 一份缓存的存储位（含 bank 填充） | 32,896 | 16,512 | -49.81% |

顶层有**两个独立 AES**，分别用于加密和完整性，并未将这两路合并。上表是先前的低面积及原高速实现的历史对比，单核的减少量不能直接等同整机百分比；两处变化以整机实际综合结果为准。

### 新增 5 拍面积优化版本

`AES_LOW_AREA=2` 保留原高速核的两轮/拍、5 拍延迟和最小 5 拍启动间隔；末拍可同时接收下一块，密钥可逐块变化。cipher 使用原 `mdm_aes128_balanced`，integrity 默认使用 `mdm_aes128_balanced_timing` 时序候选；顶层 `AES_INTEGRITY_TIMING_OPT=0` 可回退，见 [aes_balanced_hierarchy.md](aes_balanced_hierarchy.md)。`AES_LOW_AREA=0` 原高速版和 `1` 默认低面积版不变。历史参数名现为三值选择，并非布尔变量。

以下为原 balanced（非完整性时序候选）的历史数据。同用 Yosys 0.64、`synth -noabc; check -assert; stat` 对单 AES 比较：原高速版 **7,321** 个通用单元，优化版 **6,937** 个，减少 **384（5.25%）**，均为 XOR 数量变化；其他单元种类数量相同。`flatten; ltp -noff` 得到不计触发器的最长拓扑路径分别为 **70、68 层**，该指标不含工艺延时或负载，不能代替 STA。优化版以 88 XOR 的 32 位线性网络实现一列 MixColumns，同时化简第二轮密钥扩展的 XOR 依赖链；每核仍保留 40 个组合 S-box。balanced 核已将两轮的数据路径和密钥扩展拆为可例化模块；`make area-aes-balanced` 可重现该同口径对比，`make test-aes-formal` 可检查等价。

同口径 `mdm_sec` 顶层、`MAX_BYTES=2048` 的两路 AES 全部选择原高速版时为 **117,931** 个通用单元，全部选择优化版时为 **117,163** 个，减少 768（约 0.65%）；这个综合将缓冲映射到通用逻辑，目标 SRAM 宏会改变占比。可分别执行以下命令复现，并使用不同目录保存日志：

```sh
make synth-generic BUILD_DIR=build/top-fast SYNTH_MAX_BYTES=2048 SYNTH_AES_LOW_AREA=0
make synth-generic BUILD_DIR=build/top-balanced SYNTH_MAX_BYTES=2048 SYNTH_AES_LOW_AREA=2 SYNTH_AES_INTEGRITY_TIMING_OPT=0
```

新完整性候选与回退配置的同版本 Yosys 0.71 顶层通用综合分别为 **117,332 / 117,172** 个单元，单个完整性 AES 为 **7,097 / 6,937**；目标库面积和时序必须另行测量。完整参数和层次对比见 [balanced AES 层次说明](aes_balanced_hierarchy.md)。

**通用单元数不等于实际面积，也不是时序结果。** 两轮组合路径、网络 fanout、工具映射和布局布线均会影响结果；需目标工艺库与同一时钟约束下的综合、STA 和 PPA 才能确认实际面积收益及同频吞吐。模块实例路径、单核分层统计、`rc_flow` 使用注意事项及避免父子面积重复计算见 [balanced AES 层次说明](aes_balanced_hierarchy.md)；实现与接口见 [5 拍优化核规格书](specs/aes_balanced_core_spec.docx)。

缓存比较需要注意口径：旧输入缓存本身是 56,207 个通用单元，旧结果缓存是 39,810 个；新 `u_input_buffer` 同时承担输入和结果保存，单独为 56,510 个。它比旧的**输入缓存单独**略大，因为多容纳了末尾 MAC，但替代了两份缓存。地址加法优化本身只能节省约 0.5%，主要节省来自**取消第二份整包存储**，而不是声称输入存储本身减半。

### 复现

在包含基线提交的 Git 工作副本中，从仓库根目录执行：

```sh
make area-compare YOSYS=/path/to/yosys
# 汇总与完整分层报告：build/rtl/area-compare/

make synth-aes YOSYS=/path/to/yosys SYNTH_AES_LOW_AREA=1   # 默认低面积 AES
make synth-aes YOSYS=/path/to/yosys SYNTH_AES_LOW_AREA=0   # 原 5 拍高速 AES
make synth-aes YOSYS=/path/to/yosys SYNTH_AES_LOW_AREA=2   # 独立原 balanced，默认 OPT=0
make synth-aes YOSYS=/path/to/yosys BUILD_DIR=build/aes-timing SYNTH_AES_LOW_AREA=2 SYNTH_BALANCED_TIMING_OPT=1  # 时序候选
make synth-buffer YOSYS=/path/to/yosys BUFFER_CAP_BYTES=2052 BUFFER_READ_PORTS=2
make synth-generic YOSYS=/path/to/yosys SYNTH_MAX_BYTES=2048 SYNTH_AES_LOW_AREA=1
```

`make area-compare` 从 Git 的基线提交提取旧 RTL 到 `build/` 临时目录，不改工作区；如果工作副本缺少该提交，需获取分支历史。没有 Git 时也可下载[优化前提交 ZIP](https://github.com/Daliguai-sketch/MDM_SEC/archive/711947b1c08a16688d1521be45426868f4fd03e9.zip)，解压后运行：

```sh
python3 tests/compare_generic_area.py --yosys /path/to/yosys \
  --baseline-dir /path/to/old-snapshot --output build/area-compare
```

不同 Yosys 版本、综合选项及优化策略可能产生不同数量。以上数字不含实际时钟约束或 SRAM 宏；请用目标工艺库、宏、约束和布局布线重新综合并做 STA，才能判断真实面积和速度。

## 2. AES 为什么变小、如何查看各部分

原版一个 AES 每拍展开两轮：每轮 16 个数据 S-box 加 4 个密钥扩展 S-box，共 40 个并行 S-box 调用，5 拍完成一个 128 位块。旧高速实现被保存在 `rtl/mdm_aes128_fast.v`。

默认新版本 `rtl/mdm_aes128_serial.v` 在**每个 AES 核内部复用 4 个 S-box**。每轮 1 拍生成轮密钥，再用 4 拍分别处理 4 个 32 位列；共 10 轮，即从 `start && ready` 采样后的第 **50** 个上升沿产生 `done`。末拍允许同时接收下一块，无额外间隔，所以最小启动间隔也是 50 拍。两个算法通道仍各自拥有一套 AES，支持独立密钥；不会为了省面积而把 cipher 和 integrity 合成一条 AES。

默认版本不是把运算全放进 function；沿以下层次可以分别看面积：

```text
mdm_sec.u_cipher.u_aes.g_low_area.u_core       # 完整性通道另有一份同样的核
  u_shift_rows                                 # 字节连线
  u_subbytes.g_byte[0..3].u_sbox                # 4 个共享 S-box
    u_top / u_nonlinear / u_bottom              # 线性、非线性、线性部分
  u_key_expand                                  # 在线轮密钥 XOR 网络
  u_mix_column                                  # 1 个 32 位列混合单元
  u_add_round_key                               # 1 个 32 位 XOR
```

Yosys 的单核层次统计为：

| 层次 | 通用单元数 | 说明 |
|---|---:|---|
| `mdm_aes128_serial` 本层 | 1,409 | 状态/密钥/部分列/输出寄存器、复用选择、控制及初始 XOR；不含下列子模块 |
| 4 × `mdm_aes_sbox` | 476 | 每个 119；其中 `u_top` 23、`u_nonlinear` 62、`u_bottom` 34 |
| `u_key_expand` | 136 | 使用上述共享 S-box 的结果，**不要重复统计 S-box** |
| `u_mix_column` | 124 | 4 个列复用同一个单元 |
| `u_add_round_key` | 32 | 32 位 XOR |
| `u_shift_rows` | 0 | 固定连线，不代表实际布线零代价 |
| **合计** | **2,177** | 未映射到目标工艺 |

AES 包装器参数从顶层传递到两个通道：

```verilog
mdm_sec #(.MAX_BYTES(2048), .AES_LOW_AREA(1)) u_sec (...); // 默认，50 拍/块
// .AES_LOW_AREA(0) 选择原来的 5 拍/块 AES；.AES_LOW_AREA(2) 选择 5 拍优化版
```

`AES_LOW_AREA` 允许 0、1 或 2。**默认值有性能影响**：原来的 AES 为 5 拍，现在默认是 50 拍；外围不能再假设默认配置的固定响应周期为 5 拍。`AES_LOW_AREA=0/2` 分别选择原高速和新优化核，均为 5 拍延迟和启动间隔，但整机仍采用原地缓冲调度，因此不能保证整个包的周期与旧版完全相同。上面的细粒度层次表对应默认低面积版。

最小块间隔是原语数据率的上限，不是整包吞吐率。若仅举例使用 100 MHz，低面积核上限为 `128 × 100 MHz / 50 = 256 Mbit/s`，高速核为 `128 × 100 MHz / 5 = 2.56 Gbit/s`；这不是频率保证，也没有算包的装载、EIA2 的块间依赖、输出和等待。`busy` 与 `ready` 在末拍可以同时为 1，表示旧块尚在执行但可以接收下一块。

## 3. `input_buffer` 做什么，为什么大

`u_input_buffer` 现在是**整包共享缓冲**，名称沿用旧版。它不仅接收输入，还保存加解密结果；它不是 AES 的轮寄存器，也不是只缓存一个 128 位数据拍。

1. 接受命令后，先通过 `in_valid/in_ready` 装载 A，再装载 B；两段的输入 beat 各自对齐，但缓存中按连续字节存成 `A || B`，允许 A/B 在任意字节位置相接。输入端最多每拍写入 16 字节。
2. 全部装载后才启动算法。`rd0` 在运算时给 cipher 读取 B 的 32 位字，`rd1` 独立给 integrity 读取 32 位字；两路速度可不同。模式 2–5 仍在同一拍启动两条通道，也可发生同拍实际传输。
3. cipher 每次产生 1～4 字节结果，就写回原 B 对应地址。模式 1 不写回，原样 B 仍保留。模式 2 在 B 之后写入加密的 4 字节 MAC；模式 5 对尾部验证码使用滚动寄存器提取，并只输出去掉验证码的明文。
4. MAC 和 cipher 都完成后先给出响应；响应被接收后才从 `rd0` 按 128 位输出 B/结果。输出背压期间数据必须保持，整个输出握手结束后才接受下一包。因此在不改变接口协议的前提下，仍需要保存待输出的整个结果，不能简单把 FIFO 缩成几个字。

结构上有 16 个 8 位 bank，地址低 4 位选 byte bank，高位选行。共享字节旋转器支持非对齐的 128 位写/读；两个读口分别支持 128 位和 32 位，读为**异步组合读**。本次将每个 bank 的完整 16 位地址加法替换为“行地址 + 跨 bank 进位”，减少重复地址逻辑。

默认 `MAX_BYTES=2048` 时，单份缓存还需预留模式 2 附加的 4 字节：

```text
逻辑容量 = min(MAX_BYTES + 4, 65536) = 2052 字节
物理 bank 行数 = ceil(2052 / 16) = 129
存储位 = 16 bank × 129 行 × 8 位 = 16,512 位（2,064 字节，含填充）
```

旧版是输入缓存 `16×128×8=16,384` 位，加上结果缓存 `16×129×8=16,512` 位，共 `32,896` 位。两个异步读口、跨行地址、非对齐旋转、写掩码及多路选择还需要额外逻辑；如果没有匹配的存储宏，综合把存储展开为大量触发器及读选择器，面积很容易比算法本身更大。

### 原地写回的数据保护

- 模式 0：只需 cipher，B 可以直接写回；模式 1：只做完整性，B 保持原样。
- 模式 2/4：完整性需要**原始 B**，因此 cipher 只能覆盖完整性已读取的字节。完整性本拍与 cipher 写回本拍若覆盖同一字节，接收寄存器必须在写生效前采到旧值。为此，cipher 可能比旧双缓存版本多等待；模式 2 的 MAC 部分还须等待 MAC 计算完成。
- 模式 3/5：完整性需要加密/解密结果，只能读取**此前时钟沿已写回**的字节；跨 A/B 边界的 32 位字同样遵守此条件。模式 5 不把尾部 4 字节认证或输出。

上述等待不改变两条通道同拍启动，也不强制整包串行；回归检查每种模式 2–5 的 4×3 非空完整性算法组合均有实际同拍传输。但处理速度取决于相对进度：尤其模式 2/4 遇到较慢完整性通道时，原地保护会额外降低 cipher 的有效吞吐。

地址为 16 位。在 `MAX_BYTES=65535` 时实际分配完整 65536 字节环，模式 2 的末尾 MAC 可能从地址 `ffff` 回绕到 `0000`。因为 `B+4<=65535`，回绕只会覆盖已用完的 A 空间；附加 MAC 时完整性已经结束。最大长度端到端向量和独立 buffer 回绕读写测试均覆盖此情形。各 bank 的组合读在写沿提供旧值、写沿后显示新值；更换 RAM 时必须保证这一语义，不能只替换模块而忽略碰撞行为。

## 4. 还能怎么进一步优化

1. **先按系统真实最大包长设置 `MAX_BYTES`**。例如若协议明确最大 `A+B` 仅为 512 字节，设置 `.MAX_BYTES(512)` 可线性减少缓存容量；超长命令会被拒绝，不能仅为了省面积随意降低参数。
2. **针对工艺使用 SRAM/寄存器文件宏**。当前两异步读、每 bank 一写、同拍读旧值以及非对齐 16 字节写，不一定能直接推断普通单口 SRAM。可重排为较宽的 SRAM 带字节使能，采用双 bank/多端口，或将两次读取分时并增加流水与调度；非对齐 16 字节写可能跨两行，需要额外端口、bank 或周期。分时可能牺牲每拍 16 字节装载和两通道并发，复制存储又可能抵消面积收益。必须根据实际宏的端口、读延迟和读写冲突规则修改 RTL 并重新验证。
3. **减少接口带宽或引入外部包存储**。允许上游/下游提供包 RAM、重读输入、或改为流式输出，可以降低片内缓存，但会改变接口、响应先于输出的顺序、背压或系统带宽要求；当前实现未作此类协议变更。
4. **继续复用 AES 的 S-box**，例如做成每次只处理 1 个字节，可以进一步省组合逻辑，但需要更多控制/寄存器、显著增加块延迟和间隔；本次没有实现或估算其工艺面积。把加密和完整性共用一个 AES 会破坏两条通道独立计算的目标，本次没有这样做。
5. 对综合工具使用层次面积报告并检查是否发生自动 flatten；需要定位模块时可在工具中临时保留层次，再对正常优化的版本做最终 PPA 比较。保留层次可能改变优化结果。

缓存 RAM 不随复位擦除，模式 5 验证失败也不会自动阻止明文输出；系统仍须处理零化、访问控制和认证失败。具体协议、参数与限制见 [rtl_interface.md](rtl_interface.md)，验证见 [verification.md](verification.md)。
